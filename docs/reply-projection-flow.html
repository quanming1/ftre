ReplyProjection：Event 与 Msg 的边界

它不是 Event 数据库，也不是 WebSocket 队列；它是 Gateway 中把实时事件规约为可恢复消息快照的唯一领域层。

事实来源：Event 是实时过程；Msg snapshot 是会话语义与恢复事实。WS Channel 只负责传输。
CORE / PRODUCER

AgentScope / Agent Core

只负责推理并产生流式事件；不关心 WebSocket、session attach 和落盘时机。

TEXT_BLOCK_DELTA("你")
TOOL_CALL_END(...)
TOOL_RESULT_END(...)
REPLY_END
→Event
实时输入
GATEWAY / OWNER

ReplyProjection

按 reply_id 维护运行中 ReplyState；唯一负责 Event → Msg 的聚合、版本和 checkpoint。

apply(event) → Msg.content[]
revision += 1
checkpoint() → state.json
snapshot(session_id)
→实时 Event
或 attach snapshot
TRANSPORT / STORAGE

WS 与 Session State

WS 不保存会话事件历史。在线时转发 Event；attach 时读取 Projection 的完整快照。

WebSocket：实时推送
state.json：完整 Msg
客户端：按 reply_id 合并

ReplyProjection 内部流程

点击播放，可看到某个 Event 被处理时的三个动作。

1. 接收 Event

输入：TEXT_BLOCK_DELTA("好")

2. 立即聚合内存 Msg

ReplyState.message.text：
“你” → “你好”
revision：1 → 2

3. 分发与 checkpoint

向在线 WS 推送 delta。若命中边界（如 TextBlockEnd），写入完整 Msg snapshot。

不等客户端 ACK

客户端断线不能阻塞内存清理。只要完整快照已成功写入，旧实时 Event 就不再是恢复所需数据。

attach 不重放 Event

新 attach：先拿当前 reply_snapshot，然后只接收之后的新 Event。

一个 Msg，一个写入者

运行中 Msg 只能由 ReplyProjection 聚合与写入，避免 Agent、WS、SessionManager 各自维护一份。
